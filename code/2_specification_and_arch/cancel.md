# 非同期ジョブ実行エンジン 追加仕様 v1.1 — ジョブキャンセル

## 1. 概要

既存の非同期ジョブ実行エンジンに、ジョブIDを指定してジョブのキャンセルを要求する機能を追加する。

v1.0の機能および公開契約は、以下に明記する変更点を除き維持すること。

## 2. 追加する公開インターフェース

### JobStatus

既存の `JobStatus` に以下を追加する。

```python
CANCELLED = "CANCELLED"
```

### JobCancelledError

キャンセルされたジョブの結果取得時に送出する例外を追加する。

```python
class JobCancelledError(JobError):
    pass
```

### JobEngine

以下の非同期メソッドを追加する。

```python
async def cancel(self, job_id: str) -> bool:
    ...
```

既存の `submit()`、`get_status()`、`wait()`、`get_result()` のシグネチャは変更しないこと。

## 3. キャンセル要求

- 利用者はジョブIDを指定してキャンセルを要求できる。
- `PENDING` または `RUNNING` のジョブに対してキャンセルを要求できる。
- キャンセル要求を初めて受け付けた場合は `True` を返す。
- すでにキャンセル要求を受け付けているジョブに対して、再度要求した場合は `False` を返す。
- `SUCCEEDED`、`FAILED`、`CANCELLED` のジョブに対して要求した場合は `False` を返す。
- 存在しないジョブIDを指定した場合は `JobNotFoundError` を送出する。
- キャンセル要求は、対象ジョブの終了を待たずに返ること。
- キャンセル要求を受け付けた後は、対象ジョブに同じキャンセル要求を重複して通知してはならない。

`cancel()` の戻り値はキャンセル要求の受付結果であり、キャンセル完了を保証するものではない。

## 4. キャンセル処理

### 基本動作

- キャンセルはPythonの `asyncio` における協調的なキャンセルとして扱う。
- `PENDING` のジョブは、ジョブの処理本体を実行せずにキャンセルできること。
- `RUNNING` のジョブは、キャンセル要求を受けて処理を中断できること。ただし、実際の中断には対象処理がキャンセルに協力する必要がある。
- キャンセル要求を受けたジョブは、実際の終了結果に応じた終端状態へ遷移する。
- キャンセル要求直後に `CANCELLED` へ遷移している必要はない。
- キャンセルによって他のジョブの実行が中断されてはならない。

### キャンセル要求後の終了結果

キャンセル要求を受け付けた場合でも、最終状態は実行処理の終了結果によって決定する。

- `asyncio.CancelledError` によって終了した場合は `CANCELLED` とする。
- 対象処理が `asyncio.CancelledError` を捕捉し、正常終了した場合は `SUCCEEDED` とする。
- 対象処理が `asyncio.CancelledError` を捕捉し、別の例外を送出した場合は `FAILED` とする。
- キャンセル要求と正常終了・異常終了が競合した場合は、実際に確定した終端状態を維持する。

### キャンセル要求を伴わないCancelledError

- ジョブの実行処理が `asyncio.CancelledError` によって終了した場合、キャンセル要求の有無にかかわらず、最終状態を `CANCELLED` とする。
- ジョブ内部で `asyncio.CancelledError` を捕捉し、正常終了した場合は `SUCCEEDED`、別の例外で終了した場合は `FAILED` とする。
- `CANCELLED` となったジョブに対する `get_result()` は `JobCancelledError` を送出する。
- `asyncio.CancelledError` を `JobExecutionError` に変換してはならない。

## 5. 状態遷移

既存の状態遷移は以下とする。

- `PENDING → RUNNING → SUCCEEDED`
- `PENDING → RUNNING → FAILED`

新たに以下を追加する。

- `PENDING → CANCELLED`
- `RUNNING → CANCELLED`

`SUCCEEDED`、`FAILED`、`CANCELLED` は終端状態とし、一度遷移した後は変更されないこと。

状態遷移にあたっては、以下を満たすこと。

- `PENDING` のジョブがキャンセルされ、処理本体が開始されなかった場合は `CANCELLED` とする。
- ジョブの実行処理が `asyncio.CancelledError` によって終了した場合は、キャンセル要求の有無にかかわらず `CANCELLED` とする。
- キャンセル要求を受け付けたという理由だけで、実行中のジョブを終了済みとして扱ってはならない。
- キャンセル要求を受け付けた後も処理が継続し、正常終了または別の例外で終了した場合は、その終了結果を優先する。
- 終端状態に到達したジョブは、後続のキャンセル要求や他のジョブの実行によって状態が変更されないこと。

## 6. ジョブ状態照会

`get_status(job_id)` は、キャンセル完了後に `JobStatus.CANCELLED` を返すこと。

キャンセル要求を受け付けた後でも、キャンセル処理が完了していない間は `PENDING` または `RUNNING` を返してもよい。

状態照会は、対象ジョブの終了を待機しないこと。

## 7. ジョブ完了待機

`wait(job_id)` は、キャンセルされたジョブについても終端状態になるまで待機すること。

- `CANCELLED` になった場合は正常復帰し、`None` を返す。
- キャンセル要求を受け付けたという理由だけで、待機を終了してはならない。
- 既に `CANCELLED` のジョブに対して呼び出した場合は、速やかに正常復帰する。
- 複数の利用者が同じジョブを待機している場合、終端状態への遷移後に全員が復帰できること。
- 一方の待機者による操作が、他の待機者やジョブの実行に影響してはならない。

## 8. 実行結果取得

`get_result(job_id)` の振る舞いを以下のように拡張する。

| 状態 | 振る舞い |
|---|---|
| PENDING | `JobNotFinishedError` |
| RUNNING | `JobNotFinishedError` |
| SUCCEEDED | 実行結果を返す |
| FAILED | `JobExecutionError` |
| CANCELLED | `JobCancelledError` |

以下を満たすこと。

- キャンセル要求が受け付けられていても、終端状態に到達していない場合は `JobNotFinishedError` を送出する。
- キャンセル完了後は `JobCancelledError` を送出する。
- `asyncio.CancelledError` を公開APIの利用者へそのまま送出してはならない。
- キャンセル要求後に正常終了した場合は、通常どおり処理の戻り値を返す。
- キャンセル要求後に別の例外で終了した場合は、`JobExecutionError.cause` に元の例外オブジェクトを保持する。

## 9. 非機能要件

### 並行性

- キャンセル処理は他のジョブの進行を妨げないこと。
- 複数ジョブに対して独立してキャンセル要求できること。
- 同じジョブに対する複数のキャンセル要求について、最初に受け付けた要求だけを有効とすること。
- キャンセル要求の重複によって、終了処理が繰り返し中断されないこと。
- `cancel()` および `wait()` はイベントループをブロックしないこと。

### データ保持

- キャンセルされたジョブの状態は、エンジンの稼働中に参照できること。
- `CANCELLED` となったジョブは、後続の状態照会・結果取得・完了待機に対して一貫した振る舞いを維持すること。

### 互換性

- v1.0の既存機能は引き続き正常に動作すること。
- v1.0の既存公開メソッドのシグネチャは変更しないこと。
- 既存の成功・失敗・並行実行の振る舞いを維持すること。

## 10. 受け入れ条件

- [ ] PENDINGのジョブをキャンセルでき、処理本体が実行されない。
- [ ] RUNNINGのジョブをキャンセルできる。
- [ ] キャンセル要求を初めて受け付けると `True` が返る。
- [ ] 重複したキャンセル要求は `False` が返り、再度キャンセルを通知しない。
- [ ] 完了済みジョブへのキャンセル要求は `False` が返る。
- [ ] 存在しないジョブIDへのキャンセル要求は `JobNotFoundError` となる。
- [ ] キャンセル要求は対象ジョブの完了を待たずに返る。
- [ ] キャンセル要求直後に、未完了のジョブを終了済みとして扱わない。
- [ ] キャンセルされたジョブは `CANCELLED` へ遷移する。
- [ ] キャンセル完了後の `wait()` は `None` を返す。
- [ ] キャンセル完了後の `get_result()` は `JobCancelledError` を送出する。
- [ ] キャンセル要求中のジョブに対する `get_result()` は `JobNotFinishedError` を送出する。
- [ ] キャンセルが他のジョブに影響しない。
- [ ] 同一ジョブを待機する複数の利用者が、キャンセル完了後に復帰できる。
- [ ] キャンセル要求を受けた処理が正常終了した場合は `SUCCEEDED` となる。
- [ ] キャンセル要求を受けた処理が別の例外で終了した場合は `FAILED` となる。
- [ ] キャンセル要求なしで `asyncio.CancelledError` が発生した場合も `CANCELLED` となる。
- [ ] 正常終了・異常終了とキャンセル要求が競合した場合、確定した終端状態が維持される。
- [ ] 複数ジョブのキャンセルを独立して処理できる。
- [ ] v1.0の既存44テストケースが引き続き合格する。

## 11. 実装上の自由度

以下の実装方法は指定しない。

- Taskの生成・保有・検索方法
- キャンセル要求の管理方法
- ジョブと実行制御コンポーネントの関係
- クラスおよびメソッドの追加・変更
- 内部状態の保持方法
- 使用するデザインパターン

ただし、すべての公開契約と受け入れ条件を満たすこと。
